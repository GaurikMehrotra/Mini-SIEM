# Safety, privacy and threat model

Use this project only for synthetic data, public datasets whose terms you have reviewed,
and logs from an isolated lab you own. Do not ingest home, workplace, customer, or other
people's telemetry. Monitoring systems you do not own or are not authorized to monitor
can violate privacy and interception laws. This is general information, not legal advice.

The project never performs live capture, sends packets, scans a host, opens URLs from
telemetry, runs sample commands, executes upstream simulations, unpickles records,
or sends external notifications. The PCAP generator writes eight benign packets to a
file; it does not transmit them. Attack-like activity is represented only by synthetic
log strings. Do not repurpose the ingestion or sensor tools to monitor unauthorized systems.

## The SIEM is a target

Assume a log writer and a rule author can be hostile. The ingestion boundary caps lines
at 64 KiB, strings at 4096 characters, nesting at 12 and container members at 256.
Terminal control/ANSI characters are stripped from normalized fields. Raw content is
preserved as bounded data, JSON-escaped in outputs and HTML-escaped in the dashboard.
Malformed input goes to bounded quarantine. Oversized raw records and invalid UTF-8
are replaced by omission markers. Never concatenate raw fields into application logs.

Search is a hand-written grammar with an allowlist, explicit timezones, maximum 31-day
range, 500-row cap, bounded pagination and SQL parameters. SQL is not an API input.
Sigma SQL is generated by pinned pySigma, validated, parameterized and run under an
SQLite write-denying authorizer and progress deadline. RE2, not Python backtracking
regex, implements REGEXP. Rule regex length is capped at 256. YAML aliases, anchors
and explicit tags are rejected. Unsupported log sources/fields/features are reported.
Do not make the query budget unlimited to silence a failed expensive rule.

The API uses scoped keys (read, alert-write, admin, ingest), constant-time hash comparison,
a 256-KiB actual-body cap, 120 requests/minute per key or anonymous peer, and same-origin
checks. The CLI listener always binds 127.0.0.1. The Compose core uses Linux host networking
and that same loopback listener. The public dashboard shell/static files contain no logs;
all data endpoints require keys. OpenAPI JSON also requires read scope. No remote resources,
inline JavaScript, telemetry, CDN, or external webhook exists. Browser keys stay in memory,
never cookies, URL parameters or local storage. Disable API access logging to avoid leaking
query contents. There is no TLS because this is a loopback-only tool; do not expose it on
an Internet-facing interface or reverse proxy without a separate security design.

## Keys and privacy mode

`minisiem keygen` exclusively creates a mode-0600 ignored `.env`; it never prints the key.
`MINISIEM_KEYS` contains SHA256 digests and scope lists; raw key values belong only in
local environment variables or `.env`. Do not put keys in commands saved to shell history,
reports, screenshot captions, fixtures, issue text or Git. The parser rejects known
MINISIEM_API_KEY and MINISIEM_PSEUDONYM_KEY values before storing content, and HTTP ingest
rejects its supplied authentication key if echoed in a record. Hash-only key bindings
cannot identify unknown secrets embedded in arbitrary telemetry: use synthetic input,
not secret-bearing real logs. Typer's exception formatter hides locals.

For optional HMAC pseudonymization set MINISIEM_PSEUDONYM_KEY securely and pass
`minisiem ingest ... --pseudonymize`. Users, hosts and IP columns are pseudonymized.
Raw, messages, URLs, command lines, DNS/TLS names and unmapped fields are redacted because
they can leak identifiers. This intentionally trades forensic fidelity and some rules
for privacy; normal mode preserves the original raw record. Privacy mode disables
community-ID linking. HMAC identity requires the same private key on future imports.

Retention actually deletes event rows, FTS entries, links and evidence through triggers/
foreign keys, deletes old quarantine/ingest history, checkpoints WAL and compacts SQLite.
It does not promise erasure from OS backups, snapshots, SSD wear-leveling or your input
files. Delete source files separately according to their terms. Analyst notes may contain
sensitive content: use synthetic names only. Suppression needs a reason and future expiry,
and expired suppression returns to `new` while retaining its justification.

Alerts are hypotheses, never proof or instructions to act against another system.
Every alert links to its rule, author and event evidence. Sensor links add context, not
proof that an intrusion occurred. Grouping, tuning and review reduce alert fatigue.

## Publication guardrails

Only original source, rules and tiny documented synthetic fixtures belong in Git. Upstream
rules, datasets, PCAPs, telemetry, databases, `.env`, and generated evaluation artifacts
are ignored. Before committing use the final audit in docs/runbook.md. Git ignore is not
a secret scanner and does not remove already tracked secrets. Rotate a leaked key;
removing a file in a new commit does not remove it from history.


## Optional reviewed public exports

`evaluate-public` is an explicit download/evaluation command. It uses only the pinned
Splunk GitHub source, checks license/lab provenance and LFS SHA256/size before parsing,
and never follows telemetry URLs or runs upstream simulation commands. It does not run
in CI, startup, installation or default evaluation. Sysmon exported XML is bounded;
DTD/entity declarations and unexpected framing content are rejected. Public raw data and
metadata stay under ignored data/, metrics under ignored results/. Public technique-level
labels do not justify binary malicious-event labels or automated incident conclusions.
